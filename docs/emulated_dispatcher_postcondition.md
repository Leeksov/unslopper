# Emulated CFG rewrite postcondition

The emulated dispatcher rewriter has a cheap, non-mutating feasibility check. A check can predict that every father will resolve and still leave a real path into the dispatcher after block splitting. The old implementation could then emit a partly rewritten CFG that passed Hex-Rays' structural verifier but made F5 less readable.

The guarded default now permits **direct edge rewrites only**. It does not run block insertion or duplication: a detached MBA can have a different predecessor order and internal insertion state even when its serialized bytes match, so replaying an insertion plan on the live MBA can diverge after editing it. The rewriter compares the original and detached graphs, applies the direct-only rewrite to the trial, runs strict `verify(true)`, and traverses the final successor graph from the entry. It commits to the live MBA only if **every designated dispatcher block is unreachable**. Unreachable self-cycles are allowed; any surviving path to a dispatcher rejects the trial without changing the live graph. Explicit `UNSLOP_NO_GUARD=1` retains the older insertion path for diagnostics and should not be used as a normal recovery setting.

## Evidence and limits

- In `libloader` (ARM64 Mach-O, SHA-256 `aa4ba77dc142c944b64fdbd8d3fb83a38b7e7200b13cb79422dc9da88cf10970`), `0x252E74` previously reported 29 rewritten edges but left five predecessors of the dispatcher. On a fresh disposable IDB, F5 changed from 4 to 21 `goto` statements. The new trial rejects this rewrite; repeated F5 keeps 4 `goto` statements and reports zero committed edges.
- `0x22CCE8` likewise remains unchanged instead of exposing additional gotos. This deliberately suppresses some partial visual gains too: `0x256058` stays flattened because its dispatcher remains reachable.
- The first detached-trial implementation still allowed insertion and reproduced an internal error at `0xC5254`: the trial had 30 blocks after rewriting, while live replay had 31. The error counter increased after the live MBA had already changed. With insertion disabled in the guarded path, fresh repeated F5 kept the baseline `2 goto`/`1 switch` and reported zero committed edges and zero errors. `0x23B160` also remained stable in isolated trials.
- The stricter default also suppresses a previously observed full removal at `0x194F4C` (two switches to zero). This is a known coverage loss until block insertion can be planned and replayed deterministically. It is not evidence that the older rewrite was semantically correct.

The detached trial and microcode verifier establish graph integrity and dispatcher unreachability for any accepted direct-only rewrite. They do **not** prove semantic equivalence for every input or measure all Appdome families. The postcondition is exercised by a standalone CFG fixture with a surviving goto/fallthrough, an unreachable self-cycle, a reachable secondary dispatcher node, and malformed edges.
